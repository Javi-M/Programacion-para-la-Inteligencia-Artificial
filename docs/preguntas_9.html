Preguntas 9 - Clasificación I

Preguntas correspondientes al cuaderno: Clasificación I

¿Qué dos tipos de problemas de clasificación hay? ¿Por qué esa distinción?

TipSolución

De clasificación binarios y multiclase.

La relevancia de la distinción viene de que los problemas binarios se tratan de forma bastante distinguible a los multiclase. Y los multiclase, entre sí, de forma relativamente parecida.

Por ejemplo, en los multiclase la función de activación de la capa de salida será considerablemente diferente (normalmente una softmax).

En un problema de clasificación binario, basta con dar una salida \(\in [0, 1]\) representando “cuánto pertenece” a la clase positiva. En un multiclase sin embargo, si las salidas representan probabilidad de pretenencia a cada clase, hay que asegurarse que la suma sea 1.

(Repaso) ¿Para qué queremos dividir los datos en: entrenamiento, validación y test? ¿Para qué se utiliza cada conjunto?

Si el modelo devuelve un valor \(\in [0, 1]\) y las clases solo pueden ser \(\{0,1\}\)… ¿por qué no hay ningún problema? ¿Por qué no falla?

TipSolución

Porque establecemos un criterio, por ejemplo un umbral: \(0.5\), de forma que si \(M(X) > 0.5\) entonces le asignamos la clase positiva (1).

Recordatorio: \(M(X)\) es la predicción del modelo (forward) sobre el tensor de entrada \(X\).

¿Qué métricas se utilizan para evaluar un modelo de clasificación binaria?

TipSolución
  • \(Accuracy = \cfrac{TP + TN}{TP + TN + FP + FN}\)
  • \(Recall = \cfrac{TP}{TP + FN}\)
  • \(Precision = \cfrac{TP}{TP + FP}\)

donde:

  • \(TP\) - True Positives
  • \(TN\) - True Negatives
  • \(FP\) - False Positives
  • \(FN\) - False Negatives

¿Qué representa, o cómo se puede interpretar cada métrica…?

  • Accuracy
  • Recall
  • Precision

(Se puede deducir viendo las fórmulas).

TipSolución

Accuracy: representa la probabilidad de que el modelo dé la etiqueta correcta. Es decir \(P(\hat Y = Y)\). O bien: \(P(M(X) = Y)\).

Recall: representa la probabilidad de que el modelo la clasifique como positiva si la clase es positiva. \(P(M(X) = 1 | Y = 1)\). Por ejemplo: si recall = 0.8, y la clase verdadera es positiva, la probabilidad de que el modelo le asigne la clase positiva es 0.8.

Precision: representa la probabilidad de que la clase verdadera sea positiva si el modelo dice que es positiva: \(P(Y = 1 | M(X) = 1)\). Por ejemplo: si precision = 0.6, y el modelo dice que la clase es positiva, la “probabilidad” de que sea verdaderamente positiva es 0.6.

Si el accuracy fuera alto pero precision bajo, nos fiaríamos menos cada vez que el modelo diga que la etiqueta es positiva.

Nota: estoy llamando “probabilidad” a la proporción observada, que no son realmente lo mismo. Es una forma de entenderlo, pero lo más correcto es hablar de la frecuencia relativa (la proporción) sobre los datos, no de probabilidad. (Para eso habría que incluir y asumir la Ley de los Grandes Números…)

Nota: \(M(X) = \hat Y\).

¿Qué requisitos debe cumplir la función de activación para un modelo de clasificación binaria? ¿Qué opciones hay?

TipSolución

La salida debe estar entre 0 y 1. O bien se podría usar otra función y reescalarlo a 0 y 1.

Se podría incluso escoger una función \(f\) tal que \(\text{Im}(f) = [a, b]\) y reescalar de forma que \(a\) corresponda al \(0\) y \(b\) al \(1\). O incluso usar clamp para limitar la salida a 0 y 1, junto a un reescalado.

Entropía Binaria Cruzada, BCE

¿Cuál es la ecuación de la Entropía Binaria Cruzada, Binary Cross-Entropy (BCE)?

TipSolución

En los apuntes utilizamos:

\[ \text{BCE} (y_\text{pred}, y_\text{true}) = - [y_\text{true}\log(y_\text{pred}) + (1 - y_\text{true}) \log(1-y_\text{pred})] \]

En PyTorch se utiliza la expresión: \[ \ell_n (x,y) = - w_n [y_n \cdot \log x_n + (1 - y_n)\cdot \log(1 - x_n)] \]

  • (donde \(x_n = y_\text{pred}\), y \(y_n = y_\text{true}\))

Teniendo en cuenta que su uso en código es algo así:

loss = nn.BCELoss()
output = loss(m(input), target)

https://docs.pytorch.org/docs/2.13/generated/torch.nn.BCELoss.html

Nota: En PyTorch, se añade el uso implícito de un batch en la BCE, además de utilizar una función reduction (o bien mean o bien sum), para “poner en común” los valores calculados. Por eso se utiliza \(\ell_n\), representando el error del n-ésimo batch (loss n-ésimo). Si se utiliza mean, entonces el BCE final es \(\text{mean}(\ell_1, \ell_2, ..., \ell_N)\). (Sobra decir que el tamaño del batch es N).

En un modelo de clasificación binaria, con una salida \(\in [0, 1]\), ¿de qué forma se podría interpretar el valor que devuelve?

TipSolución

Como la probabilidad de que pertenezca a la clase (clase asignada al 1).

Nota (opinión mía): otra cosa que puede representar es cuánto pertenece a la clase (como si fuera un conjunto difuso). Por ejemplo: un modelo que diga si alguien es alto o no. \(M(1.75) = 0.6\), representaría que es un poco alto. Otro ejemplo, si estamos clasificando imágenes de ceros y unos, \(M(X) = 0.7\) representa cuánto la imagen parece un uno, en lugar de la probabilidad de que sea un uno.

¿Cuál es la imagen de la función BCELoss? (de PyTorch, teniendo en cuenta que maneja \(\log(0)\) como \(\log(0) = -100\))

TipSolución

\(\text{BCELoss}(X) \in [0, 100]\), desde una clasificación perfecta hasta una totalmente errónea.

TipSolución

La expresión de los apuntes es para un único ejemplo. PyTorch considera que se untilizan batches por defecto. Por eso hay que calcular la función de error \(n\) veces y luego hacer una reducción (reduction).

Si un modelo predice si estás sano (clase positiva, 1) o no (0), ¿qué es preferible, tener un mejor recall o un mejor precision?

TipSolución

Lo que no se quiere que ocurra es ignorar los casos enfermos.

Es preferible un mayor precision para la clase positiva, para reducir los falsos positivos. Que si el modelo dice que estés sano, efectivamente estés sano: \(P(Y = 1\ |\ \hat Y = 1)\). Y con ello reducir \(P(Y = 0\ |\ \hat Y = 1)\)

El recall alto es deseable para evitar pruebas innecesarias.

¿Cuál es la solución de PyTorch para evitar el problema de log(0) en BCELoss?

TipSolución

Deciden que \(\text{Im}(\log) = [-100, +\infty]\). Hacen clamp.

Para llegar a \(\log(x) = -100\), en base 2, habría que utilizar \(2^{-100}\). Para PyTorch, \(\log(0) = -100\) en lugar de \(- \infty\), evitando indeterminaciones.

Además también lo hacen por otros motivos: “This way, we can always have a finite loss value and a linear backward method.”
